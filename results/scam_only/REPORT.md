# Scam-only smishing detection - primary experiment

Generated by `src/scam_pipeline.py`, `src/scam_errors.py`, `src/scam_report.py`. Configuration, seeds, data hashes and library versions: `results/scam_only/config.json`, `results/three_class/config.json`.

## Definitions and data roles

- **Positive class = scam (smishing)** only. Normal SMS **and promotional SMS are negative**: a genuine promotion from a real company is unwanted but not fraudulent. The earlier spam+scam results are kept as a baseline experiment (`results/*.csv`, `models/final`, `models/final_v2`).
- **Training** 9447 messages; **validation** = grouped 5-fold CV on the training set (5261 groups: templates / translation sources kept in one fold).
- **Held-out test** 1589 messages (public datasets + generated / translated templates) - same distribution family as training.
- **Independent real SMS** 163 messages from Sri Lankan phones ({'spam': 98, 'ham': 36, 'smishing': 29}) - used ONLY for final evaluation (no training, tuning or threshold choice).
- Augmentation (noisy copies), TF-IDF fitting and SMOTE are done inside each training fold only.
- Threshold: chosen on CV out-of-fold scores to maximise F1 (training data only). Default-threshold results are in `metrics.csv`.
- * XGBoost row = sklearn GradientBoosting fallback (xgboost not installable here; same script uses XGBoost where installed).

## Limitations

- The real SMS set is small (163 messages, 29 scams); per-language real results (especially Tamil) are not reliable.
- The held-out test set shares sources and generation templates with training, so it over-estimates real-world performance.
- Hyper-parameters were carried over from earlier grouped-CV tuning (spam+scam labels) and not re-tuned for scam-only.
- Respondent and researcher labels agreed 73% (kappa 0.57); labels for promotional vs scam can be ambiguous.
